Bugs

Ordered by what they cost if left alone.

1. Three of the six premium features do not exist

Severity highest · Introduced today, by me · Verified source and database

I built the plan-feature mechanism and populated it with a plausible list without checking each capability was real. The gating works perfectly; three of the things it gates do not exist.

FeatureSold onReality
ota_channelsGrowth, Enterprisereal lead list, confirm, polling
advanced_reportingGrowth, Enterprisepartial two async generators; the admin page is flagged unbuilt and hidden
agent_assistantEnterprisereal
corporate_accountsGrowth, Enterprisehollow the router has a health check and nothing else; the page is flagged unbuilt
telematicsEnterprisehollow no domain, no endpoint, table has 0 rows
api_accessEnterprisehollow the key gates no route at all

An Enterprise customer today would be paying for six capabilities and receiving two and a half. Untick corporate accounts, telematics and API access on every plan until they are built — one minute on the plans page, and it is the difference between a roadmap and a misrepresentation.

2. A tenant configured for Tyro cannot take a payment at all

Severity high · Pre-existing · Verified source

gateway_factory returns TyroGateway whenever a workspace has payment_gateway = 'TYRO', and every method on it raises NotImplementedError — pre-auth, completion, incremental auth, void. Nothing stops that value being set, so the failure surfaces at the counter, mid-rental, as a 500.

StripeGateway.get_status is unimplemented too, so any reconciliation path that asks a gateway what happened to a payment raises.

3. Nothing can be upsold: no extra has a price, anywhere

Severity high, commercial · Verified production database

All five live workspaces hold nine extras each and zero are priced. An unpriced extra cannot be added to a booking, so child seats, insurance, GPS and the rest are invisible to customers and to the counter. The catalogue page I built today has the editor for this; the numbers are a business decision.

4. OTA channel webhooks raise on arrival

Severity medium · Pre-existing · Verified source

Channel.handle_webhook raises NotImplementedError with the note “implement when OTA format confirmed”. The route is mounted, so a channel that posts a booking gets a 500 and retries. Polling works, so leads still arrive — but any partner expecting push delivery is silently unserved.

5. Customer notification preference is written and never read

Severity medium · Pre-existing · Verified source

customers.preferred_channel appears nowhere in the API source. A customer who asks for SMS gets whatever the notification code defaults to. The same shape as every other bug found today: a column written by a form, read by nothing.

6. Task comments record an author nobody reads

Severity low · Verified source

task_comments.author_id is never referenced, so a comment thread cannot show who said what.

7. The revoked-token set grows forever

Severity low now, certain later · Verified Redis

revoked_tokens has no TTL and currently holds 10 entries. Every sign-out, password change and deactivation adds one and nothing removes them. A JTI is only worth remembering until the token it names would have expired anyway.

Also found, minor

  • staff_users.phone_verified_at and tax_templates.is_seed are written and never read.
  • New workspaces are provisioned with one branch, one rate code and no vehicles, so they cannot sell anything until a fleet is added. The onboarding checklist exists and says so; nothing chases it.

Feature gaps

Things absent rather than broken.

Commercial

  • Renter payment capture is unproven end to end. The Stripe path for taking a renter’s card exists and is wired, but I have not seen a real authorisation and capture run through it. Distinct from platform subscription billing, which was tested today.
  • Forward-booking import. The tenant export writes forward_bookings_for_import.csv in the layout the importer expects. There is no importer.
  • Dunning. A failed subscription payment is logged and nothing else happens — no retry schedule, no email, no escalation.

Operator tooling

  • No durable platform action log. Every console action — password resets, staff changes, plan changes, manual verification — is a structlog line, not a queryable record. For credential-affecting actions on somebody else’s account that is thin.
  • No support access. Consent-gated, read-only, time-boxed impersonation was items 7–10 of the console plan and remains unbuilt.
  • No MFA reset. If a tenant user loses their authenticator, an operator cannot clear it.
  • Sessions are unreadable. /auth/sessions returns bare JTIs — no device, no address, no last-seen — so “sign out my other devices” is a guess.
  • No notification delivery view. When a customer says an email never arrived, there is nothing to look at.

Correctness and hygiene

  • Verification tokens break when one address owns two workspaces. Known, unfixed.
  • The last platform admin can deactivate themselves, locking everybody out of the console.
  • Deleted workspaces keep their TLS certificate for roughly 90 days.
  • Open tasks are not reassigned when the person holding them is deactivated.

What is genuinely solid

Worth saying, because an audit that only lists problems misrepresents the system.

  • Tenant isolation. Every table carrying a tenant_id has row-level security; the sole exception is the platform’s own subscription mirror, which has no tenant. A lint walks the AST and fails the build on any query that touches a tenant table without a predicate.
  • Authentication. No route handler lacks an auth dependency. Platform and tenant identities are separate tables, separate cookies, separate token types, and each decoder rejects the other’s tokens by name.
  • Plan enforcement. Caps and features are enforced at every creation path, batch imports included, and a second lint asserts that every capped table reaches the limit check and that no plan column goes unread.
  • Subscription billing. Signature verification, replay protection, idempotency and term enforcement were all exercised against real Stripe deliveries today.

What I did not audit

So the coverage of this document is not overstated:

  • Business-logic correctness. Pricing arithmetic, availability, overlap detection, tax and damage workflows were not re-derived. There are 600 reservations in the demo workspace and I did not check whether their totals are right.
  • Test suite health. I ran the two isolation and enforcement lints, not the wider test suite.
  • Performance. No query plans, no load testing, no index review beyond what migrations add.
  • Frontend behaviour beyond structure and the pages touched today. Several pages I have never opened.
  • The counter application, which I have only exercised through its API.

On finding 1. I introduced it today. I built the mechanism for selling capabilities and filled it with a list that sounded right, and the one check that mattered — does each of these exist — is the one I did not run. It is the same failure this codebase keeps producing: something written, nothing reading it, nobody noticing. The lint I added catches it for plan columns and would not have caught it for plan features.
